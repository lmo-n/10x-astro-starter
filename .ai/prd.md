# Product Requirements Document (PRD): AI Flashcard Generator

## 1. Introduction

**Core Problem:** Manually creating high-quality flashcards is extremely time-consuming, creating a barrier that discourages students and individuals from using the highly effective spaced repetition learning method.
**Solution:** A web application that allows users to instantly generate flashcard sets from pasted text using AI, integrated with a built-in study system optimized for exam preparation.
**Target Audience:** High school students, university students, and individuals preparing for exams and certifications.

## 2. Success Criteria (MVP)

- **AI Acceptance Rate:** 75% of the flashcards generated by AI are ultimately accepted and saved by users (measured as the ratio of proposed cards to saved cards).
- **AI Adoption Rate:** 75% of all flashcards in the system are created using AI (compared to manual creation).

## 3. Project Scope

### In Scope (MVP)

- Quick login via Google SSO (OAuth).
- AI flashcard generation from text (Polish and English languages).
- Verification and editing screen for generated flashcards prior to saving.
- Deck management and manual flashcard creation.
- Study system based on the open-source SM-2 algorithm (tailored for quick exam cramming, not continuous language learning).
- Responsive web app (RWD) with Light/Dark mode support.
- Renewable limit system for AI generation.

### Out of Scope (MVP)

- Native mobile applications (iOS/Android).
- Custom, proprietary spaced repetition algorithm built from scratch.
- Importing PDF, DOCX files, or images.
- Sharing decks between users and social features.
- Demo/Onboarding deck (the Empty State will remain completely blank for now).
- Saving the pasted source text in the database.

## 4. Tech Stack

- **Framework:** Astro 6 SSR using React 19 Islands.
- **Styling / UI:** Tailwind CSS v4, shadcn/ui components.
- **Backend / Database / Auth:** Supabase.
- **Deployment:** Cloudflare Workers.
- **AI Models:** OpenAI API (GPT-4o-mini) or Anthropic (Claude 3 Haiku). API communication will be handled directly on the frontend.

## 5. Functional Requirements

### 5.1. Authentication & User Account

- Registration/Login exclusively via Single Sign-On (Google OAuth) handled by Supabase Auth.
- User profile in Supabase extended with specific flags: `plan_type` (default set to 'free') and `ai_credits_reset_date` to manage AI request limits.

### 5.2. Deck Management

- Ability to create, edit the name of, and delete decks.
- **Limitation:** A user can have a maximum of 120 decks. If a user attempts to create a 121st deck, the system will block the action and display a friendly message encouraging them to delete old, post-exam materials.

### 5.3. AI Flashcard Generation

- **Input limits:** The text area accepts between 5,000 and 10,000 characters of source text (copy-paste).
- **Instructions (Prompt):** An optional field below the text input allowing users to add a short instruction for the AI (e.g., "Focus only on dates and names").
- **UI/UX:** A creation animation is displayed during the API request (called from the frontend). The source text is **not** saved in the database after successful generation.
- **User limits:** Presented in a user-friendly format, such as a progress bar or a clear message (e.g., "You can generate 50 more flashcards this week"), avoiding technical terms like "API tokens".

### 5.4. Verification Screen (Preview)

- After the API returns the data, the user is presented with a list of proposed flashcards.
- Actions available on the verification screen: Quick inline editing of the text, deleting an unwanted card (via checkbox or trash icon), and a primary "Approve and save to deck" button.

### 5.5. Flashcards & Manual Addition

- **Format:** Plain Text only. No support for images or HTML formatting.
- **Physical structure:** Front – short, max 2 sentences; Back – longer, up to a 3000-character limit.
- **Manual addition:** A simple form placed inside a specific deck's view, right next to the list of already saved flashcards.
- **Database:** Each flashcard has a hidden `created_by_ai` (boolean) flag, which is essential for measuring analytics.
- **Editing during study:** If a user edits a flashcard's text (e.g., to fix a typo or clarify an answer), the system **must not** reset its knowledge metrics/intervals in the SM-2 algorithm.

### 5.6. Study Mode (Algorithm)

- Integration with a free algorithm based on SM-2.
- **Grading UX:** The bottom of the study screen features 3 or 4 classic grading buttons (e.g., Hard, Good, Easy).
- **"Exam-Focused" Approach:** The application is designed to help users "cram" for specific exams. The system provides hints and suggestions regarding the daily dose of reviews, rather than enforcing a strict, never-ending cycle typical of language learning apps.

## 6. Non-Functional Requirements (UX / UI / Error Handling)

- **Responsiveness (Mobile-First):** The UI (especially the study screen with grading buttons) must be perfectly optimized for smartphone touch screens, catering to students studying on the go.
- **Themes:** Full support for a Light / Dark Mode toggle.
- **AI Error Handling:** In the event of a Cloudflare timeout, AI API error, or content filter violation, the app must display a friendly error message, a "Try again" option, and a clear Call to Action (CTA) encouraging the user to manually create flashcards for that specific text.

## 7. User Stories

### Epic 1: Authentication & Onboarding

**1. Fast Google Login**

- **As a** student preparing for an exam,
- **I want to** log in using my Google account,
- **So that** I can start using the app instantly without creating and remembering a new password.
- **Acceptance Criteria:**
  - Login/Signup is handled exclusively via Google SSO (Supabase Auth).
  - Upon first login, a user profile is created in the `users_profiles` table.
  - The system automatically assigns `plan_type = 'free'` and sets the initial `ai_credits_reset_date`.

### Epic 2: Deck Management

**2. Creating and Organizing Decks**

- **As a** student,
- **I want to** create a new deck and give it a custom name (e.g., "Biology 101"),
- **So that** I can organize my study materials by subject or specific exam.
- **Acceptance Criteria:**
  - User can create, rename, and delete a deck.
  - The "Empty State" for a new user shows no demo decks, just a clean UI to create their first one.

**3. Deck Limit Enforcement**

- **As a** system user,
- **I want to** be notified when I reach the maximum limit of decks,
- **So that** I know I need to clean up old materials.
- **Acceptance Criteria:**
  - Hard limit of 120 decks per user.
  - Attempting to create the 121st deck disables the create button and displays a friendly message suggesting the deletion of old post-exam decks.

### Epic 3: AI Flashcard Generation (Core Feature)

**4. Pasting Text for AI Generation**

- **As a** student,
- **I want to** paste my study notes into a text box and click "Generate",
- **So that** the AI can automatically extract key information into flashcards, saving me hours of manual work.
- **Acceptance Criteria:**
  - The text area accepts between 5,000 and 10,000 characters.
  - An animation/loading state is shown while the frontend makes the API call to the AI model.
  - The pasted source text is _never_ saved to the database.

**5. Providing Custom AI Instructions (Prompts)**

- **As a** student,
- **I want to** add a short instruction below my pasted text (e.g., "Extract only dates and historical figures"),
- **So that** the generated flashcards are highly relevant to what I actually need to memorize.
- **Acceptance Criteria:**
  - Optional input field exists below the main text area.
  - This instruction is appended to the system prompt sent to the AI API.

**6. Previewing and Editing AI Output**

- **As a** student,
- **I want to** preview the AI-generated flashcards before saving them,
- **So that** I can fix minor mistakes, delete irrelevant cards, and approve only the best ones.
- **Acceptance Criteria:**
  - User sees a list of proposed cards.
  - User can quickly inline-edit the front and back text.
  - User can delete/uncheck unwanted cards.
  - Clicking "Approve and Save" saves the selected cards to the database with the `created_by_ai = true` flag.
  - The ratio of proposed vs. saved cards is logged to `ai_generation_logs`.

**7. Friendly AI Limits UI**

- **As a** free user,
- **I want to** see how many AI generations I have left in a simple, understandable way,
- **So that** I can manage my study preparation without worrying about unexpected cut-offs.
- **Acceptance Criteria:**
  - UI displays a progress bar or clear text (e.g., "You can generate 50 more flashcards this week").
  - No technical jargon like "API tokens" is visible to the user.

### Epic 4: Manual Flashcard Management

**8. Adding Cards Manually**

- **As a** student,
- **I want to** manually type out a flashcard within a specific deck,
- **So that** I can add specific questions the AI might have missed or that I thought of myself.
- **Acceptance Criteria:**
  - A simple creation form (Front, Back, "Add" button) is available inside the deck view.
  - UI enforces constraints: Plain text only, Front is short (approx. 2 sentences limit), Back has a 3000-character limit.
  - Cards saved this way have `created_by_ai = false`.

**9. Editing Existing Cards Safely**

- **As a** student studying,
- **I want to** edit a flashcard I created previously to fix a typo,
- **So that** my notes are accurate, without losing my learning progress for that card.
- **Acceptance Criteria:**
  - Updating the `front_text` or `back_text` of a card does _not_ reset its `sm2_interval`, `sm2_repetition`, or `sm2_ease_factor` in the database.

### Epic 5: Study Mode & Algorithm

**10. Reviewing Flashcards (SM-2)**

- **As an** exam taker,
- **I want to** review my due flashcards and rate how well I remembered them (e.g., Hard, Good, Easy),
- **So that** the system can schedule them for the optimal time before my exam.
- **Acceptance Criteria:**
  - Study UI displays the Front of the card.
  - Clicking "Reveal" shows the Back and displays 3 or 4 grading buttons at the bottom.
  - Selecting a grade triggers the SM-2 algorithm to update the card's intervals in the database.

### Epic 6: Non-Functional & Error Handling

**11. Mobile-First Study Experience**

- **As a** student commuting on a bus,
- **I want to** review my flashcards comfortably on my smartphone,
- **So that** I can use my idle time to study.
- **Acceptance Criteria:**
  - The study screen and grading buttons are ergonomically placed for thumb reach on mobile devices (using Tailwind RWD).
  - The app fully supports Light and Dark mode toggling.

**12. Graceful Error Handling**

- **As a** user,
- **I want to** be told clearly if the AI generation fails (e.g., server timeout),
- **So that** I understand what happened and can switch to manual entry without frustration.
- **Acceptance Criteria:**
  - If the AI API fails or Cloudflare times out, a friendly error is displayed.
  - The error includes a "Try Again" button and a clear CTA to manually add flashcards to the selected deck instead.
